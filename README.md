# Virtualizor 授权验证与更新中继服务说明

本项目通过搭建中继服务器，实现对 **Virtualizor** 授权验证的本地化管理，同时无缝透传官方更新流量，保证主控端环境的稳定运行与在线升级。

---

## 架构工作原理

中继节点通过接管 `api.virtualizor.com` 域名，针对不同协议与端口实现业务分流：

* **HTTP (80 端口) - 授权验证拦截**：部署本地 Web 服务，通过根目录下的 `license2.php` 响应客户端的授权请求，完成本地化激活认证。
* **HTTPS (443 端口) - 官方更新透传**：利用 Nginx 的 `stream` 模块在 TCP 四层直接将流量反向代理至官方服务器（`api.virtualizor.com:443`），确保软件包与内核升级不受影响。

---

## 工具脚本说明

服务端提供两套数据处理脚本，用于管理与维护授权凭证：

* **`encode.php`（授权加密）**：将自定义的 JSON 格式授权元数据（如到期时间、节点数量限制、授权类型等）编译加密，生成 `license2.php` 所需的数据密文。
* **`decode.php`（授权解密）**：用于逆向解析 `license2.php` 中的加密内容，还原并格式化输出 JSON 明文，方便校验与审计。

---

## 客户端接入指引

在需要接入激活的主控端执行以下步骤完成域名定向：

1. **配置本地解析**
修改客户端 `/etc/hosts` 文件，将官方 API 域名指向中继服务器 IP（以 `100.100.100.100` 为例）：
```text
100.100.100.100 api.virtualizor.com

```


2. **锁定 hosts 文件**
防止面板后台进程或系统脚本自动覆写解析记录，建议对 hosts 文件添加不可变属性：
```bash
chattr +i /etc/hosts

```


> **注意**：如后续需要修改或恢复解析，请先执行 `chattr -i /etc/hosts` 解除锁定。
